# HIS-13 probe artifacts

Two harnesses, because they redden two different things.

| file | what it is |
| --- | --- |
| `BASELINE.out` | a clean run, no mutation — the colour every probe is a departure from. |
| `labels.txt` | the assertion labels this suite declares, captured from the baseline. How a real assertion is told from text matched inside a failure message (M6). |
| `probes.py` | the UNIT vacuity harness. `python3 probes.py [V1 V2 …]`. Copies the production file aside, mutates, runs `jbang RunHis13.java`, restores by copying back. Asserts each mutation's pattern matched **exactly once** before applying it (mechanism C). |
| `V<n>.out` | one per probe: the mutation, the file, the branch it moves, the verdict, and **how many reds landed on a CLAIM versus on a PRECONDITION**. Truncated to 240 characters per line — see `V7.out`'s header for why. |

## Restoring after a mutation

`cp` from the saved copy. **Never `git checkout --`, `git restore`, `git stash`
or `git clean`** — DEF-035, which has now bitten four agents in this epic, two
of them after reading the entry about it. Both harnesses restore with `cp` and
delete the backup in a `finally`.

## What changed after the review of PR #244

The first version of this record was **not reproducible from the committed
harness**, and the review said so (M7). Twelve of thirteen `.out` files ended
with a javac deprecation note where the script would have written
`(no verdict line)`; the counts split three ways; and `V7.out` carried 28 copies
of an assertion belonging to a suite `RunHis13.java` does not run — lines matched
inside a multi-line failure message, not assertions.

**Every `.out` file here is now generated by `probes.py` in this directory, in
one sweep, against the source as committed.** Four things changed in the
harness, and three of them are mechanised countermeasures rather than tidying:

1. **The verdict line is found by looking for it**, not by taking the last line.
2. **Every red is classified: CLAIM or PRECONDITION**, and both counts are
   written into the file's header. This is *mechanism A moved from convention to
   code*. It immediately found five reds that the hand-written table in the goal
   contribution had credited as claims. A probe with `red on a CLAIM: 0` is
   printed with a warning and is treated as a **failed probe**.
3. **An assertion line is matched against `labels.txt`**, the label set of a
   clean baseline run, so text that merely looks like an assertion is reported
   as `[NOTE] not an assertion of this suite` instead of being counted.
4. **`EXPECTED_GREEN`** declares, up front, the one probe that is *supposed* to
   redden nothing (`V15`, the postcondition layer, which has nothing to catch
   while the layer in front of it is correct). Declared rather than discovered,
   because "this probe was green and that is fine" is precisely the sentence a
   vacuous probe wants you to write afterwards.

**The mechanised check caught something on its first run.** `V11` — which had
reddened before — came back `claims=0` after blocker 1's fix, because the new
policy gate returns before V11's line is reached. Mechanism **C**: the mutation
stopped being reachable, and a green run reads exactly like a passing check. It
was re-aimed and the missing assertion written. Nothing about that discovery
required anyone to read a transcript carefully.
