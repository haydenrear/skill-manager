=== V1  the json routing reverted — Log.console writes to stdout again
  [FAIL] in json mode no Log level writes to stdout, and stderr still gets them: stdout is reserved for the document — this is the byte that broke #235: expected <> but was <info line
  [FAIL] a CONTENDED close-out keeps stdout pure — #235's own case: and NOTHING else on stdout — THE CLAIM. The wait notice is a diagnostic and belongs on stderr: expected <> but was <home sync --dry-run: waiting for /var/…/proj — another operation in this process holds this home's lock>
  [FAIL] `skill-manager home drift --json` succeeds silently (pinned): stdout holds NOTHING but the document: expected <> but was <✓ no unread change in /var/…/home>
  FAILURES: 3

  THE HOLE THIS RUN FOUND, BEFORE THE FIX ABOVE. The contended case is the only
  one that reproduces the actual defect — a progress line on a run that
  SUCCEEDS — and its first version asserted the wait notice was on STDERR as a
  PRECONDITION:

      assertTrue(run.stderr().contains("waiting for"), "fixture precondition: …")

  Under this mutation the notice moves to stdout, so the precondition failed and
  the case reddened THERE, never reaching its claim. That is HIS-4's probe 7a
  exactly — a probe that reddens only on a precondition is not a probe of the
  claim — reproduced one epic later inside the guard written to prevent it.

  Fixed: the precondition is now stream-BLIND (the notice appeared on either
  stream, which is all "contention happened" requires), the purity assertion is
  the claim, and a third assertion checks the notice is still reported on stderr
  so the fix cannot be "delete the diagnostic". The transcript above is from the
  corrected version: it now reddens on the claim and quotes the contaminating
  line.

  Note the third failure too. `home drift --ack` is one of the PINNED silent
  paths, and it reddens under this mutation without anyone having written a case
  about drift at all. That is the pinning earning its place: the epic owner's
  instruction to pin rather than defer turned an unasserted state into a
  detector.

=== V4  close-out's frozen `if (json)` arm reverted
  [FAIL] a caught, typed refusal carries its OWN reason, not the generic one: not true: the reason is the TYPED one, not the generic "failed": [{"error":"failed","message":"home close-out --into refused: home is frozen (…)"…]
  FAILURES: 1

  The generic envelope still answers — the output stays PARSEABLE — so this
  case is not about presence. It pins the distinction between parseable and
  USEFUL: a caught exception never reaches the classifier, so only the explicit
  arm can say `home_frozen` and carry the `safe` / `blockers` fields
  close-change.sh reads. Without this case the arm would look redundant to the
  next person and be deleted.
