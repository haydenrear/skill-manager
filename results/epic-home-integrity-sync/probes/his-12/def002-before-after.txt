A NOTE ON WHAT THIS MEANS FOR THE PATH FALLBACK
-----------------------------------------------------------------------------

With step 3 alive, a real CLI invocation almost never reaches step 4: every
shipped launcher exports SKILL_MANAGER_INSTALL_DIR, so the running build
answers first. The PATH fallback is now reachable only when that back-reference
AND the jar's own location are both unavailable — and when it IS reached, the
remedy says so:

  note: this skill-manager came from PATH (<path>); nothing records it as the
  build that printed this message, and an older release answers an unknown
  subcommand with usage and exit 0. Give this home its own CLI with
  `<path> home shims` to remove the guess.

That branch is covered by HomeDescriptorCliRemedyTest ("a PATH-resolved remedy
says so; a verified one has nothing to admit"), driven through the injected
env seam rather than the ambient one, and vacuity-checked as V6.
