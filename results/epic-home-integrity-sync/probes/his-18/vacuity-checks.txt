      only be believed if the digest is what fails. The precondition was moved

      precondition") and V1 now reddens on the two hashes.

  (B) V3's FIRST run reddened case (3) with a bare NoSuchFileException path and
      no sentence at all, because `Files.readString` throws before

ONE PRECONDITION IS STILL WHERE IT REDDENS, AND IT IS RECORDED AS SUCH. Under
V1, case (3) fails on `precondition: the refresh really replaced the tree`, not
on its claim — because in the pre-HIS-18 world the child copy LOOKS edited (the
dereferenced tree is hashed), so the unit is held back and no wholesale replace
happens at all. The claim is unreachable in that world by construction. V3 is
the probe that reddens case (3)'s claim, and it is the sharper one anyway: it
disables ONLY the carry-over half, i.e. leaves HIS-4's delivered sibling doing
exactly what it already did, and case (3) still fails while (1) and (2) pass.
That is the whole reason the three cases are three.

MECHANISM B — "the fixture cannot express the defect" — is answered by case (4)
rather than by assertion: the SAME fixture with the scaffolder's ignore block
absent keeps the dereferenced trees and its two digests DIVERGE. So case (1)'s
equality is not the structural equality of two identical walks; the shape it is
asserted over really does move a digest. Case (1) additionally asserts its own
preconditions (the three paths are symlinks in the store, each resolving to a
real tree with content in it) before it asserts anything.

WHAT EACH PROBE PROVES, AND THE COLLATERAL
==========================================

V1  disables the whole change. Cases (1), (2) and (5) fail on their claims;
    case (3) fails on the precondition explained above. Cases (4) and (7) PASS,
    correctly: both are about paths the exclusion must NOT touch, and in a world
    with no exclusion nothing is touched.

V2  removes only "a tracked path is never ignored". Case (5) fails on
    `a committed file its own .gitignore matches still reaches the child home`.
    This is the clause the operator's own store forced: `spec-double-compiler`
    commits 14 files that its own `.gitignore` matches. Case (7) falls with it,
    which is the same clause at a different depth.

V3  puts `carryOverUnownedTrees` back on the Rederivable-only question — HIS-4's
    delivered sibling, untouched, doing exactly what it already did. ONLY case
    (3) fails. That is the discrimination the three-case split exists for: the
    digest half is intact, the copy half is intact, and the delivered sibling
    cannot mask the missing half.

V4  builds the design the plan rejected: `sdk`, `standard-nodes` and
    `build-logic` added to `Rederivable.OUTPUT_ROOTS` — a GLOBAL NAME LIST.
    Case (4) fails on `a unit that never declared build-logic generated keeps
    it`. The plan's argument for a per-unit declaration is therefore asserted
    rather than argued, which is what the acceptance line asked for.

V5  removes the tracked-ANCESTOR clause. Case (7) fails. This is the bug
    `sync-settles`'s OWN vacuity guard caught on the first graph run of this
    change, before any of the unit cases could see it — a tracked mode-120000
    binding was dereferenced into a subtree whose every path had a
    tracked-but-ignored ancestor, so the source walk emitted nothing for it
    while the store's own walk still emitted the tracked LINK. Case (7) exists
    so the graph is not the only thing that can catch it again.
