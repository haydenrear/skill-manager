WHAT EACH PROBE PROVES, AND EVERY CASE IT REDDENS
=================================================

V1  disables the whole change. Reddens (1) not hashed, (2) not copied, (5) the
    tracked clause's narrow half, (10) the dir-only rule, (13) the missing-index
    rule — all on their claims — plus (3) and (14) on the precondition explained
    above. Cases (4) and (7) PASS, correctly: both are about paths the exclusion
    must NOT touch, and with no exclusion nothing is touched.

V2  removes "a tracked path is never ignored". Reddens (5) `a committed file its
    own .gitignore matches still reaches the child home` and (7), which is the
    same clause at a different depth. The clause is not theoretical:
    spec-double-compiler commits 14 files that its own .gitignore matches.

V3  puts carryOverUnownedTrees back on the Rederivable-only question — HIS-4's
    delivered sibling, untouched, doing exactly what it already did. Reddens (3)
    `the excluded tree survives the wholesale replace` and (8) the teardown
    guard, which shares the same pruned enumeration. It does NOT redden (1) or
    (2): the digest half and the copy half are intact, so the delivered sibling
    cannot mask the missing half. That discrimination is why the cases are
    separate.

V4  builds the design the plan rejected: sdk, standard-nodes and build-logic
    added to Rederivable.OUTPUT_ROOTS — a GLOBAL NAME LIST. Reddens (4) `a unit
    that never declared build-logic generated keeps it`, (7), and the
    link-to-a-FILE case. The plan's argument for a per-unit declaration is
    therefore asserted rather than argued, which is what the acceptance line
    asked for.

V5  removes the tracked-ANCESTOR clause. Reddens (7) alone. This is the bug
    sync-settles' OWN vacuity guard caught on the first graph run, before any
    unit case could see it.

V6  REVIEW BLOCKER 1. Removes the teardown guard. Reddens (8) alone — `a file
    the child home wrote under an excluded path is work the parent store cannot
    be shown to have`. Without it, treeDigest hides an agent's authored file
    from "the predicate a prune, a teardown and a close-out consult before
    destroying it", and wt close deletes the child home with an empty preserve
    set.

V7  REVIEW BLOCKER 2. Reads directory-ness the way git does (NOFOLLOW_LINKS), so
    the answer moves across the dereference. Reddens (10) alone — the store's
    walk keeps `test_graph/sdk` as a LINK while the child's drops it as a
    DIRECTORY, one side hashing a path the other does not have, permanently.

V8  REVIEW MED-3. Reads a MISSING index as "nothing is tracked". Reddens (13)
    alone — the declaration becomes authoritative on the strength of a file that
    is not there, and a committed path becomes ignored after `rm .git/index`.
