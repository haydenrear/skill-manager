## Two findings the eval produced, neither caused by these PRs

**1. Dispatch from the project home was broken before either PR.**
`skt ticket new` fails there with *"bootstrap-home.sh not found in this home"*:
`git-issue-workflow` is installed in the **root** home but is absent from the
project home's `installed/` and undeclared in `skill-project.toml`. The epic
agent runs in the project home, so this fires on the next ticket dispatched.
The rollback behaved correctly (worktree removed, remedy printed). Installing
the unit into the eval fixture cleared it and the rest of the cycle was green.

**2. Merging fixes the project home and does *not* fix the root home.**
Home shims delegate to a **pinned** CLI at runtime, so who gets the fix depends
on what that pin resolves to:

| home | pin resolves to | after merge |
|---|---|---|
| project | this working tree's build | **fixed** by the merge alone — verified |
| root | a built jar artifact (2026-08-27) | **not fixed**; needs a sync/release |

Verified post-merge: project home now exports the variable, root home does not.

## Correction to my own method

A first attempt used `env -i` and reported all three arms failing, including the
fix. That was a confound in the harness, not a finding: the measurement is only
valid through the shim/`exec` path with inherited environment, which is what
HBR-4 recorded and what every arm above uses. The derivation holds on Claude
Code **2.1.252** — one patch ahead of the 2.1.251 the javadoc cites.

## Verdict

Merged. Both PRs are safe to dispatch against; #288 turns a launch that fails
into one that works and changes nothing else that was measurable here.
