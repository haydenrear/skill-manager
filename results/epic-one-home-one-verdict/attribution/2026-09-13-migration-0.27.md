## Where it craters

**The migration's safety model was built from one home's point of view.** Four of
the eight product defects are the same shape: a decision made from local,
partial state — a clone without claims, refs never fetched, a carrier matched by
spelling, a reference graph that does not know the unit was retired on purpose.
Each gate was individually reasonable; none asked "what else in this home, or
reachable from it, still believes the old shape?".

**Validation measured the mechanism, not the population.** Every test passed on
fixtures that were cleaner than any real home. The one run that found the
reinstall loop was a real project home, chosen at the user's request.

## What changed the process

- Pre-release validation runs the release candidate on REAL project homes
  (tla-spec-dev, tla-spec-dev-2, wt-oun-5, git-epic-skill, embabel-meta-skill,
  git-issue-workflow-skill, git-issue-skill, meta-orchestrator), not clones.
- The graph now carries a stale referrer naming the old repository.
- Migration guidance is printed by the CLIs at the moment it applies, and never
  written into SKILL.md or references.
