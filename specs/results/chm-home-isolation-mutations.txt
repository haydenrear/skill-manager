Mutation evidence for the `home-clone` test graph (T19 / issue #20, home-level
isolation). Recorded 2026-07-27.

Method
------
Each entry is one edit to PRODUCTION code, a full run of
`python3 skills/test_graph/scripts/run.py home-clone`, the NAMED assertions that
failed, and a byte-identity check of the restored file. The harness backs up
exactly the files it mutates and restores by `cp`; it deliberately does NOT use
`git checkout --`, because this branch carries uncommitted spec work that
`git diff --name-only` would sweep into the restore. (Learned by destroying it
once on M1 and recovering from the saved patch.)

The graph is strictly ordered, so a mutation reports at the FIRST node it
reaches. Where that is an earlier node than the one nominally under test, the
cascade is recorded rather than hidden: `home.cloned.into.project`'s independent
filesystem scan is by construction the strongest gate in the graph and catches
almost every leak before a later node can see its behavioral consequence.

=====================================================================
ARTIFACT FAULT INJECTIONS (tail nodes)
=====================================================================
Every production mutation that would make these nodes fail is caught earlier by
home.cloned.into.project's independent scan or by
home.clone.toolchains.reprovisionable, so a whole-graph mutation run cannot reach
them. These reproduce the exact on-disk state a defective clone would have
produced, then re-run one node with
`./gradlew home-clone --resume-from-build <run> --run-only-node <node>`.
No production file is touched (verified with `git status -- src/`).

FI-A  Repoint the clone's in-unit symlink ABSOLUTELY at the source home
      -> home.clone.edit.stays.in.clone FAILED
           a_write_through_the_clones_in_unit_symlink_lands_in_the_clone
           the_source_home_is_byte_identical_after_writing_through_the_clone
         (digestBefore 4e2025b1... != digestAfter d06b2861... -- the write went
          through the link into the source home)

FI-B  Delete the clone's installed/hc-unit-a.projections.json
      -> node PASSED. FINDING: BindingStore reconstructs deterministic
         default-agent bindings (`default:<agent>:<unit>`), so a missing ledger
         does not make `bindings list` lose them.
         the_clone_can_read_its_own_binding_ledger is therefore an ANTECEDENT
         GUARD, not an independent claim: its job is to stop the unbind/bind
         assertions from passing vacuously on a blank binding id, and M11 proves
         those three do fail when the id is present.

FI-C  Leave the clone's bin/cli shim body naming the SOURCE home
      -> home.clone.works.with.source.renamed FAILED
           a_bin_cli_shim_execs_the_clones_own_bytes_with_the_source_gone
         (shim exit 1 with the source renamed away)

FI-D  Leave the clone's ledger sourcePath naming the SOURCE home
      FIRST RUN: node PASSED.  <-- REAL GAP, now closed.
        Cause: `bindings list --json` prints only the target root, never
        sourcePath -- and sourcePath is the exact surface the reproduced defect
        on #20 lived on. Nothing in the node's command set printed it.
        Assertion added: the_ledgers_recorded_source_paths_name_no_missing_home,
        driving `bindings show <id> --json` with the source renamed away.
      SECOND RUN: home.clone.works.with.source.renamed FAILED
           the_ledgers_recorded_source_paths_name_no_missing_home

FI-E  Agent-home leak detection (home.clone.no.agent.home.leak).
      A production mutation here -- making AgentHomes ignore CLAUDE_CONFIG_DIR so
      the user.home fallback fires -- WOULD WRITE INTO THE OWNER'S REAL
      ~/.claude, which the standing constraint on issue #1 forbids. It was NOT
      run. Instead, a negative control: both nodes' "real home" was temporarily
      pointed at a decoy directory, a leaked unit was planted there, and the node
      re-run.
      -> home.clone.no.agent.home.leak FAILED
           the_real_claude_skills_root_is_unchanged
           none_of_this_graphs_units_appear_in_a_real_agent_home
         (claudeBefore=[] claudeNow=[hc-unit-a],
          ourUnitsInRealAgentHomes=[.claude/skills/hc-unit-a])
      Both edited node files restored and verified byte-identical.
      the_real_codex_skills_root_is_unchanged and
      the_real_gemini_skills_root_is_unchanged are the same comparison over the
      other two roots and were not separately injected.

=====================================================================
NOT PROVEN BY MUTATION
=====================================================================
Fixture guards in home.clone.fixture.built (7 of its 8 assertions) check that the
fixture really contains the artifact each later assertion is about -- an absolute
in-unit symlink, an absolute bin/cli symlink, a working shim, both a venvs/ and a
pm/ entry, aged ledgers, and a self-reference on all three surfaces. They are
sensitive by construction: deleting the planting code makes them fail, and they
exist precisely so that a downstream assertion cannot pass vacuously against an
artifact that was never created. fixture_carries_a_home_runtime_descriptor is the
exception and is killed by M16.

Antecedent guards, whose only job is to stop a later assertion passing vacuously:
  the_clone_can_read_its_own_binding_ledger      (see FI-B)
  unbind_through_the_clone_succeeds              (M11 makes bind fail alongside)
  home_describe_reads_the_clone_successfully     (exit-code guard for M8/M9/M15/M17)
  an_edit_through_the_clone_lands_in_the_clone   (guard for the source comparison)
  the_source_home_really_was_renamed_away        (guard for the four commands)
  the_source_home_was_restored                   (guard for the round-trip digest)
